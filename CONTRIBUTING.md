# Contributing to Project-Brain

Thank you for your interest in improving Project-Brain. This skill is designed to be precise, token-efficient, and universally applicable to complex AI-assisted builds. Contributions that sharpen those properties are welcome.

---

## How to Contribute

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-improvement`
3. Make your changes with clear documentation
4. Submit a pull request with a description of what changed and why

---

## Valuable Contributions

- **Enhanced trigger phrases** — better natural-language variants in SKILL.md frontmatter
- **New stack examples** — populated example projects for mobile (React Native), Rust, Go, or other stacks not yet covered
- **Refined token estimates** in `references/token-guide.md` based on real usage data
- **New AGENTS.md patterns** for domain types not yet covered (e.g., ML pipelines, data engineering, embedded systems)
- **New domain file templates** — e.g., a testing strategy template, a data flow template for ML projects
- **Real-world DECISIONS.md examples** — showing how reversal and SUPERSEDED entries look in practice
- **Corrections** to rules that turn out to be wrong or incomplete in practice
- **Compatibility notes** for agents not yet listed in README.md
- **Load Map refinements** — better L1/L2/L3/L4 classification based on real project types

---

## What NOT to Do

- Do not add project-specific features that don't generalize across stacks
- Do not remove or weaken core protocol rules (4 Invariables, Verification Gate, Red Lines)
- Do not expand the SKILL.md beyond its lean format — use `references/` for depth
- Do not add auto-commit or auto-push behavior — all git operations require explicit user approval
- Do not break compatibility with any of the supported agents listed in README.md
